# 반도체 현업 난제 분석 방법 (공개 일반 지식, 과제 무관)

과제가 수율·불량·공정·설비·계측 데이터일 때 **어떤 방법을 고르고, 무엇을 보고하고, 어디서 틀리기 쉬운지** 정리한 참고서다.
용어는 `domain/semiconductor.md`. 기준값·제외 규칙·판정 기준은 **반드시 과제 안내와 업무 담당자 확인**을 따른다.
라이브러리는 `pandas`, `numpy`, `scipy`, `statsmodels`, `scikit-learn`만으로 된다(외부 API 없음). 버전 주의는 `refs/REPOS.md`.

## 0. 공통 원칙 (평가자가 현업이다)

1. **결론을 숫자와 범위로.** "신설계안 불량률 2.1% → 1.4%, 차이 -0.7%p (95% CI -1.1 ~ -0.3), Lot 18개 중 15개에서 개선". p값만 쓰지 않는다.
2. **단위를 맞춘다.** 칩·웨이퍼·Lot 중 무엇이 독립 표본인가. 같은 웨이퍼의 칩들은 서로 독립이 아니다 → 칩 단위 검정은 유의성을 부풀린다. 웨이퍼·Lot 단위로 집계해 비교하거나, 묶음 구조를 모형에 넣는다.
3. **비교 조건을 맞춘다.** 설계안·설비·기간·제품 구성이 다르면 원값 비교는 왜곡된다(심슨의 역설). 층별(제품·설비·Lot별)로 먼저 보고 합친다.
4. **판단 기준은 담당자에게.** "얼마나 좋아져야 채택인가(실무적 의미 있는 차이)", "어떤 불량을 셀 것인가(Bin 정의)", "제외할 데이터"는 묻는다. 통계적 유의와 실무적 의미를 구분해 보고한다.
5. **재현 가능하게.** 난수 시드 고정, 정제 전후 건수, 제외 사유별 건수를 남긴다. 결과 표는 코드가 만든다.

## 1. 설계안·조건 A/B 비교 (구설계 vs 신설계, 레시피 변경, 설비 교체)

**질문 형태**: "신설계안이 불량률을 줄였나? 얼마나? 믿을 만한가? 어디서는 오히려 나쁜가?"

| 단계 | 방법 | 코드 |
| --- | --- | --- |
| 기술 통계 | 그룹별 칩·웨이퍼·Lot 수, 불량률, 웨이퍼 단위 분포(평균·중앙값·사분위) | `groupby().agg()` |
| 비율 차이 (단순) | 두 비율 차이와 95% CI, 2×2 검정 | `statsmodels.stats.proportion.proportions_ztest`, `confint_proportions_2indep`; 표본 작으면 `scipy.stats.fisher_exact` |
| 묶음 구조 반영 | 웨이퍼별 불량률로 집계 후 비교 (Welch t / Mann-Whitney) 또는 이항 GLM + 군집 강건 표준오차(Lot), 혼합효과 | `scipy.stats.ttest_ind(equal_var=False)`, `mannwhitneyu`; `statsmodels` `GLM(..., family=Binomial()).fit(cov_type="cluster", cov_kwds={"groups": lot})` |
| 짝 비교 | 같은 Lot·웨이퍼를 나눠 두 설계를 적용했으면 짝 비교 (Wilcoxon 부호순위, McNemar) | `wilcoxon`, `statsmodels...mcnemar` |
| 층별 확인 | 제품·설비·위치(중앙/가장자리)·불량 유형(Bin)별 차이. 전체는 좋아졌는데 특정 층에서 나빠지는지 | 층별 표 + Cochran-Mantel-Haenszel (`statsmodels.stats.contingency_tables.StratifiedTable`) |
| 불량 유형 변화 | Bin 분포가 바뀌었나 (불량이 줄었나, 다른 유형으로 옮겨 갔나) | 카이제곱 `chi2_contingency`, 유형별 차이 표 |
| 표본 충분성 | 이 차이를 잡으려면 웨이퍼·Lot이 몇 개 필요한가 (검정력) | `statsmodels.stats.power.NormalIndPower` + `proportion_effectsize` |
| 베이즈 요약 (선택) | "신설계가 더 나을 확률" — 현업이 이해하기 쉽다 | 베타-이항: `np.random.beta(a+불량, b+양품)` 표본 비교 |

| 비열등성·동등성 | "신설계가 기존보다 나쁘지 않다"를 보이려면 차이 없음 검정이 아니라 비열등성 검정(허용 한계 δ는 담당자와 합의). 신뢰구간의 상한이 δ보다 작으면 비열등 | 차이의 CI와 δ 비교, `statsmodels.stats.proportion.test_proportions_2indep(c1, n1, c2, n2, value=δ, alternative="smaller", compare="diff")` 또는 TOST |
| 칩 면적 정규화 | 두 설계의 칩 면적이 다르면 불량률 대신 결함 밀도 D₀로 비교. 포아송 가정 D₀ = −ln(Y)/A, 군집이 크면 음이항 Y = (1 + A·D₀/α)^(−α) | §8 수율 모델 |

**함정**: 칩 단위 검정으로 p≈0 (독립 아님) / 신설계가 다른 기간·설비에서만 생산됨 / 초기 Lot 학습효과 / 여러 Bin·층을 다 검정하고 유의한 것만 보고(다중 비교 → Holm·BH 보정 `multipletests`) / 0% 불량 그룹의 CI(Wilson·Clopper-Pearson 사용).

**담당자에게**: 채택 기준(차이 몇 %p 이상, 또는 "나쁘지 않으면 채택"인지와 허용 한계), 어떤 Bin, 리페어 전·후 중 어느 수율, 두 설계가 같은 조건에서 생산됐는지, 칩 면적이 같은지, 제외 Lot(재작업·엔지니어링·hold).

## 2. 웨이퍼 맵 패턴

| 목적 | 방법 |
| --- | --- |
| 위치 효과 | 중심에서 거리(반지름)·구역(중앙/중간/가장자리, 사분면)별 불량률. 가장자리 링, 중앙 원, 한쪽 쏠림 |
| 군집 여부 | 불량 칩 인접 비율 vs 무작위 기대(순열 검정), 연결 요소 크기 |
| 패턴 분류 | 규칙 기반(반지름·각도 특징) 먼저. 라벨이 있으면 특징 + `RandomForestClassifier`; 없으면 `KMeans`/`DBSCAN`으로 묶고 대표 맵 확인 |
| 시각화 | die_x, die_y 격자 히트맵 (설계안별·Bin별 나란히) |

| 샷·레티클 반복 | 샷 안 칩 위치(shot 내 좌표)별 불량률을 모든 샷에 걸쳐 합산. 특정 위치만 높으면 레티클 결함 |
| 결함 검사 연결 | 인라인 결함 좌표를 칩에 매핑해 "결함이 떨어진 칩의 불량률 / 안 떨어진 칩의 불량률"(킬러 비율) |

**함정**: 가장자리 칩은 원래 불량률이 높다 → 설계 비교 시 위치 구성 차이 보정. 좌표계(노치 방향, 원점 위치) 확인.

## 3. 공정 관리 (SPC, 공정능력)

| 목적 | 방법 |
| --- | --- |
| 관리도 | 개별값 I-MR, 부분군 X̄-R, 불량률 p-chart (표본 크기 다르면 한계가 점마다 다름) |
| 이탈 규칙 | 한계 밖 1점, 같은 쪽 연속 N점(보통 7~9), 연속 증가·감소 6점 (Western Electric·Nelson). 몇 개 규칙을 쓸지 담당자 확인 |
| 기준 기간 | 안정 구간으로 한계를 정하고 이후를 판정 (같은 데이터로 한계를 정하고 판정하면 이탈이 묻힌다) |
| 공정능력 | Cp, Cpk = min(USL-μ, μ-LSL)/3σ. 정규성 확인, 장기 σ vs 단기 σ 구분 |
| 다변량 | 센서 여러 개: Hotelling T², PCA 잔차(SPE) |

## 4. 원인 좁히기 (Commonality, 변화 시점)

| 목적 | 방법 |
| --- | --- |
| 공통 설비·챔버 | 저수율 Lot이 거친 설비·챔버·시간대별 비율 vs 전체 비율 (리프트), 카이제곱·Fisher, 다중 비교 보정. Lot 수가 적은 그룹은 표시만 |
| 혼재 보정 | 제품·레시피별 기준 대비 편차로 비교, 또는 로지스틱 회귀에 제품·설비 동시 투입 |
| 변화 시점 | 누적합(CUSUM), 이동평균 차이, 구간 평균 비교. PM·레시피 변경 이력과 맞춰 본다 |
| 큐타임 | 단계 사이 대기 시간 구간별 불량률. 허용 한계 근처에서 꺾이는지 |
| 중요 변수 | 트리 모델 중요도 + 순열 중요도(`sklearn.inspection.permutation_importance`). 상관이지 인과가 아니라고 명시 |

## 5. 예측·조기 경보 (수율 예측, 불량 예측, 이상 탐지)

| 목적 | 방법 |
| --- | --- |
| 기준선 | 먼저 단순 규칙·평균 모델의 성능을 잰다. 복잡한 모델은 이것보다 나을 때만 |
| 모델 | `HistGradientBoosting*`, `RandomForest*`, 로지스틱 회귀(설명 쉬움) |
| 검증 분할 | **Lot·웨이퍼 단위로 나눈다**(`GroupKFold`). 시간 순서가 있으면 과거로 학습, 미래로 평가(`TimeSeriesSplit`). 칩을 무작위로 나누면 누설로 성능이 부풀려진다 |
| 불균형 | 불량이 드물면 정확도 대신 재현율·정밀도·PR-AUC, 임계값을 비용 기준(놓친 불량 vs 오경보)으로 담당자와 정한다 |
| 이상 탐지 | 라벨 없으면 `IsolationForest`, 강건 z-score(중앙값·MAD). 오경보율을 정상 기간에서 측정 |
| 가상 계측 | FDC 요약으로 계측값 회귀 예측. 실측된 웨이퍼로 Lot 단위 검증, 오차를 규격 폭 대비로 보고 |
| 설명 | 중요 변수 상위 5개, 부분 의존(`PartialDependenceDisplay`), 경보 1건의 사유 |

## 6. 결과를 현업에게 보여 주기

- **한 장 요약**: 결론 1문장 → 핵심 숫자 3개(범위 포함) → 권고 → 한계·추가 확인 → 다음 단계. 양식: `templates/REPORT.md`.
- **그림 3개면 충분**: 그룹 비교(점+CI), 층별 차이(나빠진 층 표시), 웨이퍼 맵 또는 추이. 축 단위·표본 수 표기.
- **"이걸로 무엇을 결정할 수 있나"**: 채택/보류/추가 실험(웨이퍼 몇 장 더) 중 하나를 권고하고 근거를 붙인다.
- **AI 활용 설명**: AI가 한 일(코드 작성·검정 후보 제시)과 사람이 한 판단(기준·제외 규칙·채택 권고), 검증 방법(손 계산, 시뮬레이션, 테스트)을 구분한다.

## 7. 검증 방법 (분석 코드)

- **알려진 답이 있는 가짜 데이터**로 파이프라인을 먼저 돌린다: 차이 0과 차이 있음 두 경우를 시뮬레이션해 검정이 맞게 반응하는지(1종 오류·검정력) 확인.
- 작은 표(2×2)는 손 계산과 비교하는 테스트를 붙인다.
- 집계 단위(칩→웨이퍼→Lot) 변환 전후 합계가 같은지 테스트.
- 같은 입력에 같은 결과(시드 고정) 테스트.

## 8. 수율 모델 (면적·결함 밀도·적층)

| 모델 | 식 (A = 칩 면적, D₀ = 면적당 결함 밀도) | 언제 |
| --- | --- | --- |
| 포아송 | Y = e^(−A·D₀) | 결함이 고르게 흩어진다고 볼 때, 빠른 추정 |
| 음이항 | Y = (1 + A·D₀/α)^(−α), α가 작을수록 군집 | 결함이 몰릴 때. 같은 D₀에서 포아송보다 수율이 높게 나온다 |
| 머피 | Y = ((1 − e^(−A·D₀)) / (A·D₀))² | 웨이퍼마다 결함 밀도가 다를 때 |
| 적층(HBM 등) | Y_stack ≈ Π Y_die × Y_bond | 다이 수율 작은 차이가 단수만큼 증폭. KGD 선별 효과 계산 |

- 설계 비교에서 칩 면적이 다르면 D₀로 바꿔 비교하고, "면적 차이로 설명되는 수율 차이"와 "남는 차이"를 나눠 보고한다.
- 군집(α)은 웨이퍼별 수율 분산이 이항분포보다 큰지(과대산포)로 확인한다.

## 9. 설비 운영·배정 (최적화 과제)

- **기준선 먼저**: FIFO, 납기 우선(EDD), 임계 비율(CR) 같은 디스패칭 규칙으로 기준 KPI를 낸 뒤 개선안을 비교한다.
- **리틀의 법칙**: WIP = 처리량 × 사이클 타임. 병목 설비의 가동률이 1에 가까워질수록 대기가 급격히 늘어난다(대기행렬 이론). 병목 가동률을 함께 보고한다.
- **제약 예**: 큐타임 한계, 레시피·설비 자격(어떤 설비가 어떤 레시피를 할 수 있나), 셋업 시간, 정비 일정, 배치(여러 lot 동시 처리) 크기.
- **KPI**: 사이클 타임(평균·p90), 납기 준수율, 큐타임 위반 수, 설비 가동률, 셋업 횟수. 하나만 좋게 하면 다른 것이 나빠지므로 표로 같이 보여 준다.
- **정비 과제**: MTBF·MTTR, 계획 정비 vs 고장 정비 비율, 정비 직후 수율·센서 변화(§4 변화 시점).
