# skill: review — 읽기 전용 점검 (감시 점검 / 교차검증)

**이 절차를 따르는 동안 어떤 파일도 수정하지 않는다. 명령은 읽기·테스트 실행만 한다.**
메인은 결과를 받은 뒤 수용·수정·거절과 이유를 DECISIONS '서술형 재료 5. AI 협업·검증 기록'에 남긴다.
결과는 목록으로만 보고하고, 수정은 메인 세션이 판단한다.

## 모드 A: 감시 점검 (작업 중간)
입력: 남은 시간 N분
1. `REQUIREMENTS.md`, `git log --oneline`, 테스트 결과를 확인한다.
2. 보고:
   - 필수 요구사항별 완료 / 부분 / 미착수 (증거 커밋 해시)
   - 남은 N분 기준 위험 3개 (예: 미착수 필수가 많음, 테스트 없음, 문서와 코드 불일치)
   - 다음 작업 순서 제안 (필수 우선, 각 예상 소요)
   - 지금 멈추고 정리해야 할 것이 있으면 맨 위에

## 모드 B: 교차검증 1 (합의 직후)
1. 과제 안내의 필수조건과 `PLAN.md`, `REQUIREMENTS.md`를 비교한다.
2. 보고: 빠진 조건, 서로 모순되는 내용, 아직 모호해서 담당자에게 물어야 할 점

## 모드 C: 교차검증 2 (제출 직전)
1. 문서(`REQUIREMENTS`, `HANDOFF`, `DECISIONS`, README)에 "완료"라고 쓴 항목마다 코드·테스트·커밋이 실제로 있는지 대조한다.
2. 테스트를 실행한다(실행 0건·건너뜀만 있으면 '미검증').
3. 보고: 불일치 목록(문서 위치 → 실제 상태), 실패 테스트, 제출 파일 누락
