# 서술형 질문 은행

K14가 이 질문들을 **내 저장소의 실제 아키텍처**(DESIGN, evidence, 코드)로 답한다. 해당 없는 질문은 "해당 없음: 이유"로 남긴다.
각 질문 옆 [근거]는 답을 찾을 곳이다. 질문은 **아주 구체적으로** 나온다고 가정하고 답한다(예: "핵심 알고리즘을 어떻게 짰고 무엇을 버렸나", "입력 파일을 어떤 모듈로 어떻게 전달했고 어느 함수가 담당했나").

## A. 핵심 알고리즘과 트레이드오프 [DESIGN §4, 핵심 함수]
1. 핵심 문제를 한 문장으로 정의하면? 입력·출력·목표·필수 제약은?
2. 알고리즘을 단계별로 설명하라 (함수 이름 순서대로).
3. 왜 이 방법인가? 검토한 대안 두 개와 버린 이유는? (최적해 vs 휴리스틱, 정확도 vs 속도, 단순함 vs 확장성)
4. 이 방법이 나쁜 답을 내는 입력은? 실제로 확인했나?
5. 최적이 아닐 때 얼마나 차이 나는지 어떻게 알 수 있나? (하한, 비교 기준, 지표)
6. 결과가 실행마다 같은가? 동점·순서는 어떻게 고정했나?
7. 시간 복잡도와 실제 측정 시간은? N이 10배가 되면?
8. 시간이 더 있었다면 무엇을 바꾸겠나?

## B. 데이터 파이프라인 [DESIGN §2·§3, evidence 소스 지도]
9. 입력 파일이 화면까지 가는 경로를 단계별로 (적재 → 검증 → 저장 → 계산 → API → 화면).
10. 각 단계를 맡은 모듈·함수는? 왜 그렇게 나눴나?
11. 검증은 어디서 하나? 잘못된 파일이 들어오면 사용자에게 무엇이 보이나?
12. 데이터가 교체되면 이전 결과는 어떻게 되나? 교체가 실패하면?
13. 여러 파일을 어떻게 연결(조인)했나? 키가 안 맞는 행은?
14. 원본 데이터를 바꾸나? 정제 규칙은 어디에 기록했나?
15. 같은 데이터로 다시 돌리면 같은 결과가 나오나? (재현성)

## C. 서빙·배포·운영 [DESIGN §2 서빙, §6, evidence 배포 단서]
16. 서비스는 어디서 어떻게 실행되나? (프로세스, 포트, 바인딩, 컨테이너)
17. 계산은 언제 하나? 요청 때 / 미리 / 시작 시, 그 이유는?
18. 상태는 어디에 저장되나? 재시작하면 무엇이 남나?
19. 동시에 두 명이 실행하면? 중복 클릭은?
20. 설정·비밀값은 어떻게 관리하나? 운영 환경으로 옮길 때 바꿀 것은?
21. 장애를 어떻게 알아차리나? (헬스체크, 로그, 오류 메시지)
22. 권한은 어디서 검사하나? 화면에서만 숨긴 것은 없나?

## D. 기준값 설계 [DESIGN §5, DECISIONS]
23. 이 기준값(예: 거리·시간 임계값)은 어떻게 정했나? 담당자 확인인가, 내 가정인가?
24. 경계값(정확히 기준과 같은 경우)은 포함인가? 반올림은 비교 전인가 후인가?
25. 기준값을 어떻게 계산했나? (직선거리 vs 실제 경로, 속도 가정)
26. 강제 규칙인가 평가 지표인가? 어기는 답은 버리나 점수만 깎나?
27. 기준값이 바뀌면 코드 어디를 고치나? 운영자가 직접 바꿀 수 있나?
28. 기준을 만족하는 답이 없으면 어떻게 하나?

## E. 예외·엣지 케이스 [DESIGN §8, `skills/edge-cases`]
29. 휴무·결근인 대상은 어떻게 처리했나? 빠지면 결과가 어떻게 바뀌나?
30. 야간·교대처럼 성격이 다른 집단은 섞었나 분리했나? 왜?
31. 자정을 넘기는 시간, 시간대가 다른 시각은?
32. 결측·중복·참조 깨짐·불가능한 값이 있으면? 조용히 고친 것은 없나?
33. 용량·정원을 넘으면?
34. 0건·1건·대량일 때 화면과 계산은?
35. 가장 까다로웠던 예외 하나: 어떻게 발견했고 어떻게 고쳤고 어떻게 확인했나?
36. 처리하지 못한 예외는? 왜 미뤘나?

## F. 코드 검증 [evidence 테스트, DECISIONS 서술형 재료 6, HANDOFF, check.sh 결과]
37. 정확성을 무엇으로 확인했나? 테스트가 무엇을 고정하나 (기준값 경계, 예외, 필수 규칙)?
38. 결과가 필수 규칙을 지키는지 자동으로 검사하나? (생성 후 검증 함수)
39. 손으로 계산한 기대값과 비교한 사례는?
40. 화면은 어떻게 확인했나? (역할별, 빈 상태, 오류 상태)
41. 테스트로 잡은 실제 버그는?
42. 검증하지 못한 부분과 그 위험은?

## G. AI 협업 [DECISIONS 서술형 재료 5·6, AI_COLLABORATION, 커밋 흐름]
43. AI에게 무엇을 맡기고 무엇을 직접 정했나? 그 기준은?
44. AI 결과가 틀렸던 사례와 어떻게 알았나?
45. AI 제안을 거절하거나 뒤집은 판단은? 이유는?
46. 승인 흐름(계획 → 승인 → 구현)이 실제로 막아 준 것은?
47. 서브에이전트·리뷰를 어떻게 썼고 무엇을 받아들이고 버렸나?
48. 비용(토큰)을 어떻게 관리했나?
49. AI가 만든 코드를 내가 설명할 수 있다고 어떻게 보장했나?
50. 다시 한다면 AI 활용에서 무엇을 바꾸겠나?
