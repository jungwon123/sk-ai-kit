# skill: essay-brief — 서술형 브리핑

후속 서술형(AI·복사 없이 6문항 × 5분)은 **내가 만든 것**을 깊게 묻는다. 이 절차는 그 답의 재료를 **사실만으로** 한 장에 모은다.
**코드·테스트·커밋에 없는 내용은 쓰지 않는다.** 확인하지 못한 것은 "미확인"이라고 쓴다. 문장은 짧게, 각 줄에 근거(`파일:줄`, 테스트 이름, 커밋)를 단다.

## 절차

1. `python3 scripts/evidence.py`로 `out/evidence.md`를 만든다(저장소를 통째로 읽지 않는다).
2. `out/evidence.md`, `DESIGN.md`, `DECISIONS.md`(서술형 재료 포함), `HANDOFF.md`, `REQUIREMENTS.md`를 읽는다. 핵심 함수는 evidence의 줄 번호로 **그 범위만** 연다.
3. 아래 양식으로 `ESSAY_BRIEF.md`를 쓴다. 각 절의 "30초 답변"은 **사실 → 이유·대안 → 약점 → 검증·개선** 순서 4문장 이내.
4. `skills/essay-brief/QUESTIONS.md`의 질문 50개에 **내 아키텍처로** 답한다. 질문마다 3줄 이내: 답(사실·함수·숫자) / 근거(`파일:줄`, 테스트 이름, DM 시각) / 약점 한 줄. 해당 없으면 "해당 없음: 이유". 같은 답이 반복되면 "→ A3과 같음"으로 줄인다. 결과는 `ESSAY_QA.md`.
   과제 고유의 질문도 5개 이상 추가한다. 내 기준값·예외·데이터 열 이름을 넣어 **구체적으로** 만든다(예: "야간 근무자 12명은 왜 별도 그룹으로 뺐나").
   하나 이상은 **구현하지 않은 것을 전제로 한 질문**으로 만들고, 답에 "그 기능은 없다. 대신 ○○로 처리했다"를 적는다.
5. 문장 교정이 필요하면 `skills/fluent-korean/SKILL.md`를 적용한다(내용·숫자 변경 금지). 커밋 `[DOCS] 서술형 브리핑`.

## 양식 (ESSAY_BRIEF.md)

```markdown
# ESSAY_BRIEF (작성: HH:MM, 커밋 <해시>)

## 0. 한 문단 요약
무엇을 누구를 위해 만들었고, 핵심 숫자 3개(데이터 규모, 결과 지표, 테스트 수).

## 1. 핵심 알고리즘과 트레이드오프
- 목표·필수 규칙:
- 절차 (함수:줄):
- 고른 방법 vs 대안 | 얻은 것 | 잃은 것 | 버린 이유:
- 복잡도·실측 (N, 시간):
- 30초 답변:

## 2. 데이터 파이프라인과 서빙
- 흐름: 입력 → 적재·검증 → 저장 → 계산 → API → 화면·내보내기 (단계별 담당 함수:줄)
- 언제 계산하나 (시작 시 / 요청 시 / 미리 계산), 상태는 어디 남나 (DB·메모리·파일)
- 서빙: 프로세스·포트·바인딩·컨테이너, 헬스체크, 재시작 시 남는 것/사라지는 것
- 데이터가 바뀌면: 재계산 흐름, 이전 결과 표시 방식
- 30초 답변:

## 3. 기준값 설계
| 기준 | 값 | 근거(담당자 확인 시각 / 내 가정) | 경계 처리 | 강제 규칙/평가 지표 |
- 30초 답변:

## 4. 예외·장애 처리 (DESIGN §8에서 옮김)
| 사례 | 근거 | 처리 방식 | 위치 | 화면 표시 | 테스트 |
- 처리하지 않은 케이스와 이유:
- 가장 까다로웠던 것 1개 (원인 → 해결 → 확인):
- 30초 답변:

## 5. 코드 검증과 AI 협업
- 검증 수단: 자동 테스트 N개(무엇을 고정했나), 직접 실행·브라우저 확인, reviewer 점검(몇 번, 무엇을 찾았나), check.sh
- AI가 만든 것 중 고치거나 거절한 사례 2개 (무엇이 틀렸고 어떻게 알았나). 출처: DECISIONS 서술형 재료 5·6
- 오류·수정 기록에서 가장 의미 있는 1건: 발견 → 원인 → 수정 → 재발 방지 테스트
- 검증하지 못한 것 (미확인 목록)
- 30초 답변:

## 6. 한계와 다음 단계
- 규모가 10배·100배가 되면 먼저 느려질 곳과 대안:
- 운영 배포 전 남은 일:

## 예상 꼬리질문
(절마다 2개, 한 줄 답 골격. 하나는 미구현 전제 질문)
```

## 하지 않을 것

- ESSAY_BRIEF는 2쪽 이내로 쓴다(5분 안에 다시 말할 수 있는 분량). 자세한 내용은 ESSAY_QA에 둔다.
- 문서에만 있고 코드에 없는 기능을 쓰지 않는다. 테스트 이름으로 확인되지 않은 동작은 "미확인"이다.
