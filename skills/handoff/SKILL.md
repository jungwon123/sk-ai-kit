# skill: handoff — 인수인계 문서 작성과 세션 교체

## 언제
- 작업 중간(대화가 길어져 앞 내용을 놓치기 시작할 때, 또는 정해 둔 시점)
- 마감 직전 (아래 '마감 체크리스트'까지 수행)

## 절차
1. `git log --oneline`, `git status`, `REQUIREMENTS.md`, `DECISIONS.md`를 읽는다.
2. 테스트를 실행해 현재 통과/실패 수를 확인한다(0건·건너뜀만이면 '미검증'으로 쓴다).
3. `HANDOFF.md`를 **현재 코드·커밋 기준으로** 갱신한다.
   - 현재 상태: 완료 / 진행 중 / 미착수를 요구사항 ID로 (완료는 증거 커밋 해시와 함께)
   - 실행 방법: 설치·서버·테스트 명령을 실제로 동작하는 그대로 (서버는 0.0.0.0, 포트 명시)
   - 구조: 데이터 → 계산 → API → 화면 흐름과 핵심 파일 3~5개
   - 주요 결정: DECISIONS에서 가장 중요한 3개
   - 알려진 약점·위험: 데이터 가정, 예외 처리 공백, 성능, 규칙 기반 해석의 한계(임계값 근거, 다루지 못하는 경우) 등 **구체적으로**
   - 다음 할 일: 우선순위 순 3개 이내
   - 비용 기록: 사용자가 알려준 체크포인트별 `/status` 토큰 사용량, 서브에이전트 사용 횟수와 용도
4. 안 된 것은 안 됐다고 쓴다. 문서에만 있고 코드에 없는 기능이 없어야 한다.
5. `[DOCS] handoff 갱신`으로 커밋한다.
6. 새 세션에서 쓸 첫 문장을 출력한다:
   `AGENTS.md, HANDOFF.md, REQUIREMENTS.md를 읽고 현재 상태를 3줄로 요약해 확인받은 뒤, 다음 미완료 요구사항부터 이어서 해.`

## 마감 체크리스트 (마감 시에만)
- [ ] REQUIREMENTS 상태가 실제 구현·테스트와 일치
- [ ] DECISIONS의 각 결정에 근거·검증 결과가 있고, 남은 한계가 적혀 있음
- [ ] PLAN의 성공 기준에 대해 현재 결과가 어떤지 한 줄씩 적음
- [ ] README(또는 실행 문서)의 명령을 그대로 따라 하면 재현됨
- [ ] 키·토큰 하드코딩 없음 (`bash scripts/check.sh`)
- [ ] 과제 안내가 요구한 제출 파일이 모두 정해진 경로·이름에 있음
